# 组序贯上线设计

`data/plan.json` 是上线前冻结的登记计划。`look` 命令只按这份计划读取数据；修改计划字段会改变计划指纹，既有台账会拒绝继续。

## 登记内容

| 字段 | 含义 |
| --- | --- |
| `alpha` | 双侧总误报率，由 `spending` 在计划观察点分配 |
| `sides` | 只支持 `2`（双侧） |
| `outcome.amountCap` | 用户级购买金额的截尾上限，必须在看数据前登记 |
| `outcome.perUserAggregation` | 先按用户求和再截尾（`sum-then-cap`）或逐行截尾再求和 |
| `arms` | 对照/实验组标签、随机化单位（只支持 `user`）与分配比例 |
| `information.rule` | `eligible-users`：按隔离冲突后的合格用户数计信息量 |
| `information.maxUsers` | 最大信息量对应的用户数 |
| `looks.fractions` | 累计信息比例，严格递增且最后一个为 1 |
| `spending.type` | `obrien-fleming`、`pocock` 或 `power`（需 `gamma`） |
| `numerics` | 数值积分阶数、比较阶数、收敛容差、迭代上限与有限样本校正方式 |

## 信息量与观察点

第 _i_ 个观察点在合格用户数达到 `round(fractions[i] * maxUsers)` 时触发。未达到时请求只返回 `pending`，**不消费观察点**，也不产生 p 值。观察点由计划决定，不能改用“效果最显著的那天”。用户按 `visible` 与用户键稳定排序后取累计前缀，先前的观察点队列被冻结；若冻结用户的金额或分组被改动，请求会被拒绝，更正须走 `supplement`。

每次 `look` 最多消费一个观察点，重复提交同一累计导出幂等。同一份导出在计划结束后再次提交也返回原状态，不产生新决定。

## alpha-spending 与边界

累计 alpha 由所选设计给出：

- O’Brien-Fleming：`2 - 2Φ(z_{1-α/2} / sqrt(f))`
- Pocock：`α · log(1 + (e - 1) f)`
- Power：`α · f^γ`

`design` 命令按累计检验统计量 `Z_i` 的相关结构 `cov(Z_i, Z_j) = sqrt(f_i / f_j)` 求解各观察点边界，而不是把 alpha 平均分给每次。求解方式：用高斯-勒让德积分递推各观察点保留区域的密度，再对下一条边界做二分；输出用更高积分阶数与更小容差重算，`numerical.boundaryShift`、`massError`、`spendingResidual` 记录近似误差。若误差超过阈值，命令直接拒绝输出。

求解得到的边界基于已知方差的正态模型。实际统计量用两组各自的小样本方差估计分母，尾部比正态更重；`numerics.finiteSample: "student-t"` 会把每个边界乘以同一观察点上 `t` 分位数与正态分位数的比值。自由度取单组在该观察点的用户数减一（两组合计的一半），不只依赖用户总数。校正只使用登记的观察点规模，不看观测数据；若某观察点每组少于 3 人，计划会被拒绝。关闭校正只能通过显式 `"none"`，且模拟会显示误报率偏高。

报告分两层：`numerical.finiteSample.calibratedBoundaries` 是实际使用的边界；`numerical.massError` 等误差指标针对正态模型求解步骤。`normalModelCrossing` 记录正态模型下每个观察点的累计交叉概率，它应等于 `cumulativeAlpha`；有限样本校正后的实际误报率由模拟给出，并在小样本下略低于名义值。

假定：信息比例由合格用户数决定；结局为每用户截尾金额且组内独立；每用户恰好属于一组；边界只在计划观察点适用；组间方差齐性（校正按每组的合并自由度处理）。

## 台账

`--store` 指向的 JSON 保存：

- 计划指纹与设计快照（含边界、alpha 累计值、相关矩阵、数值误差）；
- 每次观察点当时的可见用户数、实际统计量、边界、累计截尾金额与 `continue`/`stop`/`final-no-reject`；
- 冻结队列的指纹与用户键；
- 已停止/完成后追加的补充分析（`affectsDecision: false`）。

台账写入使用排他锁与临时文件替换；并发请求不会互相覆盖。重启后同一份导出仍是幂等的，因为幂等判断依据的是输入指纹而不是进程内状态。

补充分析保留原始统计量，但明确标注 `decisionRule: descriptive-only` 与 `affectsDecision: false`；它不消耗观察点，也不改变停止/完成状态。

## 模拟

`simulate` 用可配置的 `runs`、`seed`、`users`、组均值、标准差、截尾上限和分组污染率，在零效应下重放整条决策路径，报告误报率、Wilson 区间、按观察点的停止次数，以及“每天重算名义 p 值”会达到的对比误报率。模拟与正式分析共用 `analyzeSequence`，因此测的是实际会执行的规则。小规模演示的区间很宽，只用于检查实现方向。

用演练计划（96 名用户、3 个观察点、student-t 校正）每个随机种子跑 10000 次零效应模拟，6 个种子合并 60000 次的误报率为 0.0484；逐种子结果约在 0.046–0.051 之间。同一批数据若每次都用 0.05 的名义双侧 p 值判断，误报率约为 0.10。若把有限样本校正关掉，合并误报率约 0.058，明显高于名义 0.05。这些数值来自合成正态（前端在 0 处截断）金额，不构成对真实业务的保证。
